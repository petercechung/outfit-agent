# Demo script (2–3 minutes)

Before recording: open https://stylist.cechung.com once so the FashionCLIP container is awake (a cron keeps it
warm every 20 minutes), and clear the browser's site data if you want a first-time state.

**0:00 — The problem (20 s).** Shopping sites take keywords; people speak in situations. Type
「下週一面試，想要簡約但不要太死板」 and start talking while it thinks.

**0:20 — Thinking out loud (20 s).** The stylist's plan streams in as it is written: what it understood, four
different looks, and every garment with a reason. Say the point: nothing in our code knows what an interview
needs — the agent decides, then searches product photos for what it described.

**0:40 — The looks (30 s).** Three complete outfits with prices. Open 造型分析 on one: it compares the outfit with
the request and with this week's fashion headlines (Vogue Taiwan, WWD), and names one thing to change.

**1:10 — Feedback, the judges' test (30 s).** Type 「我從來不穿黑色」. The looks come back without black, and the
toast says the stylist remembered. Open 我的 → 造型師記得的你 and show the paragraph — editable, in plain language.

**1:40 — Proof it gets better (20 s).** 我的 → 進步驗證: the same simulated shopper, with and without the memory.
Show the numbers: black 81% → 0% when the memory says 「不穿黑色」.

**2:00 — The loop back to the brand (30 s).** 設計師洞察: what people asked for today becomes 開款・選款・備料
decisions — 「米色」佔需求 28%、只佔商品 8% → 備料; 「海邊」的整套找不到 → 開款. Sentences are de-identified first.

**2:30 — Close (15 s).** One sentence in, three purchasable outfits out, an explanation you can argue with, and
demand signals the brand can act on. Repo, README, live site.

## If something goes wrong on stage

- Slow first answer → the container was asleep; say so, the plan still streams while it wakes.
- The critic keeps fewer than three looks → it judged the rest unsuitable; open 造型分析 to show why.
- The site is down → v1 is still live at https://outfit.cechung.com.
